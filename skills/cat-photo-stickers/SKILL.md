# 猫咪原照表情包

目标：文件夹里每张原照片各做一张正方形表情包。照片铺满画布，文字在照片内，保留猫的真实神态。默认 512×512、中文、16 张；数量和尺寸按用户指定。仅用本地图片处理与排字，不需要图像生成 API。所有交付图片均为真正的 PNG 编码，包括单张表情包、封面、图标和预览。

## 读取整批照片

拿到用户提供的本地文件夹，递归索引其中所有支持的照片。没有路径时才询问路径。用下面的 `index` 命令生成编号联系表和 `catalog.json`，加载联系表后逐张查看原图。不能仅凭缩略图或文件名写文案。对手机照片先按 EXIF 修正方向；坐标也以修正后的图像为准。

默认应有 16 张；不是 16 张时报告实际数量。用户说“处理文件夹全部照片”而未限定数量时使用实际数量，build 传 `--count N`。明确要求 16 张而文件数不符时先解决缺图/多图，不擅自选 16 张、重复用某张凑数或略过损坏文件。HEIC/RAW 在不覆盖原文件的情况下转换到独立工作目录再索引，保留原照与转换照的对应记录。字节完全相同的重复文件需先说明并处理，不能当不同动作使用。

默认把最终结果保存在用户提供的照片文件夹内的 `表情包结果/` 子目录，包含单图、预览和 ZIP；不要另存到旁边的同级文件夹。已存在结果时使用 `表情包结果-02/`、`表情包结果-03/` 等新目录，不覆盖原照或旧结果。用户明确指定其他输出位置时遵从。索引、裁切计划、manifest 放在输入目录内的隐藏工作目录 `.cat-photo-stickers/`，每次用新子目录。索引自动跳过隐藏目录、`表情包结果` 及其版本目录，以及带 `.cat-photo-stickers-output` 标记的其他结果目录，避免把成品再次当原照。私有照片与成品不要写进 skill 安装目录或待发布的代码仓库。

## 逐张设计：表情、裁切、文案、位置

给每张照片记录一行计划 `plan.md`：编号、来源、可见神态/动作、短句、裁切坐标、文字区域、猫脸/关键动作保护区域。**每张独立判断**，不把同一句、同一裁切或同一文字位置机械套用整批。

- 根据眼神、嘴形、耳朵、姿态和交互拟自然口语短句，通常 2–8 个汉字；优先贴合照片，不强凑预设的 16 种情绪。保留用户给定的文字。
- 选择源照片中一个正方形裁切，突出猫脸与动作。必要时可舍去无关背景或身体下部，但不要无意裁掉耳尖、关键爪子或道具。多猫画面保留用户指定主体。
- 成品必须是原照**铺满的正方形**：不添加白边、卡片边框、底部文案栏，不把竖照缩小摆在白色画布上。无法在正方形内同时保留所有部位时，优先神态和动作，向用户说明实际取舍。
- 文字直接叠在照片中的空闲区域：上方、左右、角落或画面内下部都可，但不能放在图片外。位置随照片内容变化，避开眼睛、鼻嘴、耳朵和关键动作。可先选短句/换行，再调整区域；不要为了塞文字挡脸。
- 默认不加描边、边框或阴影：深色背景用纯白字，明亮背景用纯黑字，按每张文字区域的背景选择。只有用户明确要求时才加描边。使用支持中文的本地字体，不随仓库分发未经许可的字体。字形覆盖需实际检查，尤其 emoji。

把裁切与叠字参数写进 `manifest.json`。坐标定义见 [references/manifest.md](references/manifest.md)。每条都需要实际观察后标记的 `protected_regions`，至少包含猫脸；它们用于脚本的几何重叠检查，并不是自动识别猫脸。保护区域正确与否仍需视觉复核。

## 本地脚本

依赖：Python 3.9+、Pillow。优先用已有 Pillow 的环境，否则建虚拟环境并安装本 skill 的 `requirements.txt`。命令中的 `<skill-dir>` 替换为本文件所在目录，路径含空格时加引号。

```bash
python3 <skill-dir>/scripts/photo_stickers.py index --photos /path/to/16-photos --out /path/to/16-photos/.cat-photo-stickers/run-01/catalog
python3 <skill-dir>/scripts/photo_stickers.py build --manifest /path/to/16-photos/.cat-photo-stickers/run-01/manifest.json --font /path/to/chinese-font.ttf
```

build 检查整个 catalog 与 manifest 的来源一对一匹配、数量、重复文件、正方形裁切、文字与保护区域重叠；任一条失败则修正该条后再导出。build 默认 16 张，其他数量用 `--count N`；大小用 `--size N`。省略 `--out` 时脚本自动选择输入文件夹内的结果子目录并避开已有版本；显式指定的输出目录必须不存在，不覆盖原照或旧成品。

输出：`stickers/` 中的 PNG 单图、`preview.png` 四列预览、`cover.png` 正方形封面、`icon.png` 正方形图标、`captions.json`、`stickers.zip`。仅本地使用的 `source-map.json` 记录原照对应关系；ZIP 包含单图、封面、图标和文案，不含源路径与原照片。

## 封面与图标

每套额外生成 `cover.png` 和 `icon.png`，均为正方形 PNG，不能只改扩展名。默认封面为 1024×1024，将整套成品排成方形拼图（16 张时为 4×4），不加外置文案栏。默认图标为 512×512：从本套原照中选一张清楚、有辨识度的猫脸，独立选择正方形裁切，不叠字、不画框、不从带字成品截取。选择结果写入 manifest 顶层 `icon`，格式见引用说明。用户指定其他尺寸或封面样式时按其要求调整。封面/图标是额外素材，不占用 16 张原照的一对一表情包名额。

## 检查与交付

加载预览，并逐张查看成品，确认：每张原照各对应一张表情包；单图/封面/图标均为正方形且实际编码是 PNG；封面排版完整、图标猫脸清楚且无字；照片铺满无外置文案栏；文字准确清晰、未超边缘、未遮住脸与动作；文案符合该张照片。位置有问题就改该张 manifest，而不是重做全部设计。

用户已经要求整批制作时，直接完成整批，不添加计划确认环节。给出预览、ZIP、单图目录与本地计划位置。若用户只提供一张试做，就输出一张，不复用为 16 张。线条/简笔画属于另一个 skill，本 skill 不把原照描边当作线条插画交付。
